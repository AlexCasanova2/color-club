# Agent Notes

## Project Context

- App: Color Club, a React Native/Expo mobile app backed by Supabase.
- Main branch: `main`.
- Expo SDK: `~54.0.36`.
- Local validation uses `npm test`, `npm run typecheck`, `npx expo-doctor` and `git diff --check`.
- Supabase migrations live in `supabase/migrations/` and are applied manually or with `supabase db push`.
- Never record a presumed remote migration here. Check the linked Supabase project or ask the user before asserting remote migration state.

## Product Rules

- The UI should stay playful, colorful and rounded.
- Preserve the floating black bottom dock and the sticky black capsule header pattern.
- Internal screens such as challenge creation, chat, club management and edit profile hide the bottom dock.
- Toasts must use `src/components/Toast.tsx` so the progress bar reaches the measured full width before the toast fades out.
- Public profiles must not expose `email`, `friend_code` or notification/privacy preferences.

## Implementation Notes

- Navigation is manual in `App.tsx`; there is no router package.
- Most domain operations are in `src/lib/api.ts`; session, profile, Storage and some Realtime subscriptions access Supabase directly.
- Domain types live in `src/types/domain.ts`.
- Shared UI primitives live in `src/components/ui.tsx`.
- Color tokens live in `src/lib/theme.ts`.
- Chat uses `club_messages` and Supabase Realtime.
- In-app notifications use `notifications` and Supabase Realtime. Current types are `challenge`, `friend_request`, `club_invite`, `weekly_summary` and `reengagement`.
- Challenge activity notifications use `dedupe_key` to avoid duplicates and are generated by `submit_collage`, `advance_challenge` and `advance_challenges`.
- Club invites use `club_invites`, `invite_user_to_club` and `respond_club_invite`; invitations are accepted explicitly before adding rows to `club_members`.
- Public profiles are rendered by `src/screens/PublicProfileScreen.tsx`, loaded through `getPublicProfile`, and include contextual friendship actions.
- Public profile statistics are loaded through `get_user_stats` / `getUserStats`; keep future achievements derived from these server-side stats or a server-side achievements table, not client-side counters.
- Friend search previews use `search_public_profiles` / `searchPublicProfiles` and must not expose `friend_code`.
- Clubs allow at most 12 active members and support `member`, `moderator` and `admin` roles. `clubs.admin_id` remains the primary owner.
- Challenge presets are `30min`, `2h`, `6h`, `24h`, `48h` and `1week`; photo counts are the even values from 2 through 12.
- The client starts challenges immediately even though the RPC supports `begins_at`. Do not document scheduled starts as a client feature.
- Voting is skipped and the challenge closes directly when two or fewer collages were submitted.
- The current client has no router. The `web` script exists, but required Expo Web dependencies are not installed.

## Database Notes

- Do not assume migrations are applied remotely unless the user confirms it.
- New schema changes should be added as a new numbered migration, not edited into an already-applied migration unless explicitly requested.
- Weekly summary notifications require scheduling `create_weekly_summary_notifications()` in Supabase Scheduler/Cron.
- Challenge deadline reminders require scheduling `create_challenge_deadline_notifications()` in Supabase Scheduler/Cron.
- Re-engagement notifications require scheduling `create_reengagement_notifications()` daily in Supabase Scheduler/Cron.
- Push notifications are sent by `supabase/functions/send-push-notification`; it must fail closed if `PUSH_WEBHOOK_SECRET` is missing and the webhook must send `x-push-webhook-secret`.

## Git Notes

- Check `git status --short`, `git diff` and recent commits before committing.
- Do not revert unrelated local changes.
- Commit only after validations pass unless the user explicitly asks otherwise.
